## 회의 조율(Meeting Poll) 엣지케이스 — 오늘 반드시 확인

이 도메인이 스프린트 전체에서 가장 복잡했던 만큼, 아래 엣지케이스들을 놓치기 쉽습니다.

- [ ] **팀원이 한 명도 응답 안 한 상태**에서 마감 시각이 지나도 조율이 안 망가지는지 (자동 집계 로직이 없어도, 최소한 조회/확정 API가 에러 없이 동작해야 함)
- [ ] **미응답자가 있는 슬롯을 `force:false`로 확정 시도** → 정확히 `UNANSWERED_EXISTS` 반환
- [ ] **동점 슬롯**(가능 인원이 똑같은 슬롯 여러 개)이 있어도 프로젝트장이 임의로 아무거나 선택해서 확정 가능한지 (자동 정렬/추천만 하고 강제 선택은 안 하는지 재확인)
- [ ] **확정된 조율을 취소 후 재조율** → 새 슬롯이 기존 것과 안 섞이는지 (새 `MeetingPoll` row로 완전히 분리되는지)
- [ ] **참가 명단을 일부만 지정**(`memberIds`)했을 때, 명단에 없는 팀원은 응답 화면 접근 시 403이 뜨는지
- [ ] 팀원이 중도 이탈한 뒤에도 이미 진행 중이던 조율이 에러 없이 유지되는지 (이탈자의 기존 응답은 그대로 남아도 무방하지만, 새로 집계할 때 이탈자를 카운트에서 빼는 게 이상적 — 시간 되면 확인, 안 되면 알려진 이슈로 남겨두기)

## 채팅(Chat) 연결 안정성 — 오늘 반드시 확인

- [ ] 브라우저 새로고침 후 WebSocket 재연결이 되는지
- [ ] 같은 채팅방을 여러 탭/기기에서 동시에 열었을 때 메시지가 양쪽 다 실시간으로 보이는지
- [ ] 서버를 재시작해도(로컬 개발 중 흔한 상황) 클라이언트가 무한 에러 없이 재연결을 시도하는지(프론트 담당 영역이지만, 서버가 재연결 요청을 정상적으로 받아주는지는 확인)
- [ ] 이미지 업로드(REST) 후 WebSocket으로 전송한 메시지가 채팅 내역 조회(8-3)에서도 동일하게 나오는지 (REST와 WebSocket 두 경로가 같은 MongoDB 컬렉션에 정확히 쓰고 있는지)

## End-to-End 시나리오 (B트랙 중심)

1. [ ] (인원1 API로) 공고 작성 → 지원 → 수락
2. [ ] 그룹 채팅 생성(Project 전환) → 팀원 확인
3. [ ] 채팅으로 메시지/이미지 주고받기
4. [ ] 회의 조율 개설 → 전원 응답 → 최종 확정 → 팀 캘린더 반영
5. [ ] 팀원 한 명 불참 처리 → 채팅방에 시스템 메시지 확인
6. [ ] 프로젝트 연장 → 다시 종료
7. [ ] (인원1 API로) 상호평가 작성 → AI 피드백 생성 확인
8. [ ] 프로젝트 나가기/퇴출 → `Recruit.currentCount` 감소, 채팅방에서도 제거 확인
