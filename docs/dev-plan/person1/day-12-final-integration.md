## End-to-End 시나리오 (실제 사용자처럼 처음부터 끝까지)

1. [ ] 회원가입 → 로그인
2. [ ] 프로필(이력서) 작성
3. [ ] 공고 작성 (다른 계정으로 로그인해서) → 지원 → 댓글 작성
4. [ ] 지원자 수락 → 그룹 채팅 생성(Project 전환)
5. [ ] 채팅방에서 메시지 주고받기(WebSocket), 이미지 전송
6. [ ] 회의 조율 개설 → 응답 제출 → 최종 확정 → 캘린더 반영 확인
7. [ ] 팀 일정 확인, 참석/불참 변경
8. [ ] 프로젝트 종료
9. [ ] 상호평가 작성 (전원) → AI 피드백 자동 생성 확인
10. [ ] 알림 목록에 지금까지의 이벤트(지원/수락/댓글/회의확정/평가요청 등)가 잘 쌓였는지 확인
11. [ ] 마이페이지에서 지원현황/작성공고/스크랩/평가 내역이 다 보이는지
12. [ ] 로그아웃 → 재로그인 → 토큰 갱신까지 정상 동작

## 배포 전 체크리스트

- [ ] `application.yaml` / `application-local.yaml`에 하드코딩된 비밀값(JWT_SECRET, MAIL_PASSWORD 등)이 없는지, 전부 환경변수로 빠졌는지 확인
- [ ] `.env` 파일이 `.gitignore`에 포함되어 커밋 안 됐는지 확인
- [ ] `SecurityConfig`의 permitAll 목록에 공개 API(공고 조회, Master Data, 인증 관련)가 전부 포함되고, **비공개 API가 실수로 permitAll에 들어가 있지 않은지** 재점검
- [ ] `docs/API_SPEC.md`, `docs/ERROR_CODE.md`, `docs/ENUM.md`가 실제 구현과 어긋나는 부분 없는지 (특히 오늘까지 스코프 조정하며 목업으로 대체한 AI 기능들, 생략한 배치 작업은 문서에 "현재 목업/미구현" 표시를 남겨두면 나중에 헷갈리지 않습니다)
- [ ] `./gradlew build` 전체 빌드 성공 확인
- [ ] 남아있는 `// TODO` 주석 전체 검색(`grep -rn "TODO" src/main`)해서, 데모/제출에 치명적인 것만 추려서 처리
- [ ] Docker Compose(`docker compose up -d`)로 완전히 새로 띄운 환경에서도 앱이 정상 기동하는지 (로컬 캐시/기존 데이터에 의존하고 있지 않은지)
