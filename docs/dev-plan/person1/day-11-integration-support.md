# Day 11 — 버그수정 + B트랙 통합 지원

오늘은 새 기능을 만드는 날이 아니라, **지금까지 두 사람이 따로 짠 코드가 실제로 맞물리는지 확인하고 고치는 날**입니다. 인원1은 이번 스프린트에서 여유 시간이 더 있으니, 오늘은 인원2 쪽 진행 상황을 봐가며 유동적으로 지원해주세요.

---

## 결합 지점 총정리 (A↔B 트랙이 서로 코드를 부르는 지점)

### ① 인원1 → 인원2 코드를 호출하는 곳

| 위치 | 내용 |
|---|---|
| `ApplyService.updateStatus()` (4-8, Day7에서 작성) | 지원 수락 시 이미 Project가 생성된 공고라면 `ProjectRepository.findByRecruitId()`, `ChatRoomRepository.findByProjectId()`를 호출해서 `ProjectMember`/`ChatRoomMember`를 자동 등록 |
| `FeedbackService` (4-9~4-12, Day10에서 작성) | `Project.isEnded()`, `Project.getUpdatedAt()` 등 인원2가 만든 `Project` 엔티티 필드/메서드를 그대로 사용 |

**오늘 할 일**: Day7 때 주석 처리해뒀을 수 있는 4-8의 Project/ChatRoom 연동 블록을 실제로 살려서 컴파일/동작 확인하세요.

### ② 인원2 → 인원1 코드를 호출하는 곳

| 위치 | 내용 |
|---|---|
| Project 종료확인/연장/종료 알림 (6-4, 6-5) | 인원1이 Day9에 만든 `NotificationSender.send(...)` 호출 필요 |
| 회의 조율 개설/마감임박/확정 알림 (7-10, 7-13) | 동일 |
| 그룹 채팅방 공지, 새 지원자 알림 등 | 동일 |
| 팀원 퇴출/탈퇴 시 `Recruit.currentCount` 감소 (6-6, 6-7) | 인원1이 Day7에 추가한 `Recruit.increaseCurrentCount()`의 짝인 `decreaseCurrentCount()` — 없으면 오늘 같이 추가 |

**오늘 할 일**: 인원2 코드에서 `NotificationSender`를 잘 가져다 쓰고 있는지, `Recruit.decreaseCurrentCount()`가 실제로 존재하고 호출되는지 확인. 없으면 지금 추가해서 인원2에게 바로 공유하세요.

## 확인 시나리오 체크리스트 (실제로 순서대로 호출해보기)

- [ ] 회원가입 → 로그인 (완료된 것 재확인)
- [ ] 공고 작성(3-2) → 다른 계정으로 지원(3-11)
- [ ] 작성자가 지원자 목록 조회(4-7) → 지원자 수락(4-8)
- [ ] **[인원2 코드 필요]** 작성자가 그룹 채팅 생성(6-1) → Project 생성 확인, `Recruit.status`는 안 바뀌는지(OPEN 유지) 확인
- [ ] 이후 추가로 들어온 지원자를 수락(4-8) → **Project가 이미 있으니 자동으로 ProjectMember + ChatRoomMember 등록되는지** (오늘 가장 중요한 검증)
- [ ] **[인원2 코드 필요]** 프로젝트 종료(6-4) → 알림 발송 확인(NotificationHistory에 실제로 쌓이는지)
- [ ] 종료된 프로젝트로 상호평가(4-10) 작성 가능한지
- [ ] 전원 평가 완료 시 AI 피드백(4-12) 자동 생성 확인

## 오늘의 우선순위

1. 위 체크리스트를 실제로 Swagger/curl로 처음부터 끝까지 한 번 돌려보기 (가장 중요)
2. 걸리는 지점마다 즉시 수정, 인원2와 실시간으로 맞춰가며 진행
3. 시간이 남으면: Day10에서 미뤄둔 AI 피드백 3일 경과 배치(`@Scheduled`) 추가, Day9에서 미뤄둔 알림 발송 연동 마무리
4. `SecurityConfig`의 permitAll 목록이 지금까지 만든 모든 공개 API(공고 목록/상세, Master Data 등)를 빠짐없이 포함하는지 전체 재점검
